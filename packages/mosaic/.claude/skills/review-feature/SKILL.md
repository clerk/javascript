# review-feature

Lint checks syntax and a few banned calls. It cannot see a missing model, a guard copied into a second place, or a hand-built version of a shared helper. This skill reviews a feature for that drift and returns a table. It is ephemeral like the [parity audit](../../../docs/parity-audit.md): the table guides the work and the PR discussion, then is discarded.

The rules live in the docs. Each check below names the question to ask and the section that owns the rule. Read the section, then judge the code against what it says. When a check and its doc disagree, the doc wins; fix this file.

## Run it

Run it as a read-only subagent. It reads and runs `git` and `rg`; it never edits, commits or checks out a branch in your worktree. Hand it this prompt with the blanks filled:

```
Follow packages/mosaic/.claude/skills/review-feature/SKILL.md in the repo at <repo-root>.
Target: <feature folder, e.g. packages/mosaic/src/features/api-keys/>
  or <branch or PR, diffed against <base>, e.g. origin/main>
Write the findings table to <absolute path>, and return it.
```

To review a branch you have not checked out, add a detached worktree for it outside the repo and point the subagent there: `git worktree add --detach <scratch>/<name> origin/<branch>`. Remove it afterwards with `git worktree remove <scratch>/<name>`.

## Step 1: scope

- **Folder:** every file in the folder, plus every Swingset file that imports from it: `rg -l "features/<path-under-src/features>" packages/swingset/src`. Swingset imports by package path (`@clerk/mosaic/features/...`), so do not search for relative imports.
- **Diff:** `git diff --name-only <base>...HEAD`. The feature folder is the main target. Every other changed file is in scope too: a shared part changed for the feature (check S1), a fixture holding logic (check M1), a doc edited to allow what the feature does.

Read `packages/mosaic/AGENTS.md` and `packages/mosaic/ARCHITECTURE.md` → "Flow and data architecture" first. Then read each doc a check names before you judge that check.

## Step 2: checks

Run every check. A check whose files the target does not have is `n/a`, with the reason.

### Model

| ID  | Ask                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Owner                                                                                  |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| M1  | Is there a `*.model.ts(x)`, and is it the only file that imports Clerk hooks or calls resources? `rg -n "@clerk/(shared/react\|react)\|useClerk\|useOrganization\|useUser\|useSession" <feature>`. If there is no model, find where the data comes from instead: a `*Data`/`*Source` prop the wrapper takes, a story fixture that builds it, logic (state, async, derivation) in `packages/swingset/` that a model should own. A fixture is a finding only when the feature ships no model or no wrapper, so the fixture is the only place the data, saves or wiring exist. If the feature ships its own model and wrapper, its fixture is a story harness and not a finding, even when it calls the controller. | AGENTS.md → "Layers in one paragraph"; models.md intro; ARCHITECTURE.md → "File shape" |
| M2  | For each hand-written type in `*.types.ts` (and inline types in the model and controller): does `@clerk/shared/types` already have it? Search by the domain noun and its union values: `rg -n "<Noun>(Resource\|Mode\|Status)\b\|'<value>' \| '<value>'" packages/shared/src/types`. A copied union, or an object mirroring a resource's fields, is a finding; name the Clerk type it should `Pick` or reuse.                                                                                                                                                                                                                                                                                                    | models.md → Rules ("Derive plain data types from `@clerk/shared/types`")               |
| M3  | Is the model's return a discriminated union on `status`, rather than `isLoaded`/`isLoading` flags beside the data?                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | models.md → "Shape"                                                                    |
| M4  | If the Clerk hook takes a search query, page or sort, does the model hold it and expose a callback that changes it (`search(query)` sets the query and returns to page 1)? A query passed into the model as a hook argument, or a page reset done with an effect on the query, is a finding.                                                                                                                                                                                                                                                                                                                                                                                                                     | models.md → Rules ("The other exception is what to fetch")                             |

### Controller

| ID  | Ask                                                                                                                                                                                                                                                                                                                                                                                             | Owner                                                                                                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | Does a value computed outside a machine or form (`canContinue`, `isValid`, `canX`) repeat a machine `guard` or a `useForm` `canSubmit`? Compare their conditions line by line.                                                                                                                                                                                                                  | views.md → "Take derived booleans from the controller", "Forms on a card" (the controller owns `canSubmit`)                                                                            |
| C2  | Does a transition's `actions` do anything besides `assign` or log? | C3  | Is one action's busy or pending state held in two places: a machine state plus `usePendingAction`, `useForm.isSubmitting` plus a `useState` flag, two `usePendingAction`s for one action? | C4  | Is `useForm` used for a step that submits no values, or whose `onSubmit` only moves to the next step? | C5  | `try`/`catch` (or `.catch`) around a model callback or Clerk call in a controller or view, or a Clerk error turned into a string. | C6  | Does the controller return a machine `snapshot` or `send`? ### View

| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| V1  | Does a view work out what the controller should hand it? Three kinds, each owned by the doc: (a) a guard or "is this allowed" check the controller or machine already has; (b) which step, screen, footer, back action or dialog to show, picked from a data field (`request.kind === …`) or a step comparison outside `Flow.Root value`; (c) `.filter`/`.find`/`.sort`/grouping over a data list to decide what goes where. Not findings: picking display copy or a color for a value, or hiding UI on an absent callback. | V2  | Does one screen replace another with a conditional or early return instead of `Flow`? ## Step 3: report

Verdicts:

- **fail**: the code contradicts a sentence in the owning doc. Quote the code's `file:line` and name the doc section.
- **ask**: the doc requires a decision the code cannot show, such as an ask-first trail for a shared change.
- **pass**: checked, nothing found. Say what you checked in a few words.
- **n/a**: the target has nothing this check applies to.

A finding needs both a `file:line` and a doc rule it breaks. If no doc states the rule, it is not a finding; list it under "Not covered by a doc" below the table, so the docs can decide. Do not report style preferences, lint-level issues or naming.

A code site the owning doc names as its own example passes that rule, even when another sentence seems to forbid it.

One row per finding. Sites of the same problem go in one row. Order: fail, ask, then pass and n/a.

Keep "Not covered by a doc" to the five items a doc owner most needs to decide, one line each.

```md
| Check | Verdict | Where                                  | Finding                                                    | Rule                                     |
| ----- | ------- | -------------------------------------- | ---------------------------------------------------------- | ---------------------------------------- |
| C2    | fail    | `feature/x.controller.ts:88`           | `COMPLETE` action calls `context.onComplete()`             | AGENTS.md → Shaping a fix → Machines     |
| S1    | ask     | `components/dialog/dialog.tsx:40`      | New `scope` prop on `Dialog.Popup`, added for this feature | AGENTS.md → When nothing fits: ask first |
| T1    | pass    | `feature/__tests__/x.feature.test.tsx` | Feature test against `serveFapi`                           | testing.md → Feature tests               |
```
