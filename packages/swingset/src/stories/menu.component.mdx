## Usage

```tsx
import { Icon } from '@clerk/mosaic/components/icon';
import { Menu } from '@clerk/mosaic/components/menu';
import { LogOut } from '@clerk/mosaic/icons/glyphs/log-out';
import { Plus } from '@clerk/mosaic/icons/glyphs/plus';
import { X } from '@clerk/mosaic/icons/glyphs/x';

<Menu.Root>
  <Menu.Trigger />
  <Menu.Popup>
    <Menu.Item label='Add organization'>
      <Menu.Media>
        <Icon glyph={Plus} />
      </Menu.Media>
      <Menu.Label>Add organization</Menu.Label>
    </Menu.Item>
    <Menu.Item
      label='Sign out'
      onClick={signOut}
    >
      <Menu.Media>
        <Icon glyph={LogOut} />
      </Menu.Media>
      <Menu.Label>Sign out</Menu.Label>
    </Menu.Item>
    <Menu.Item
      label='Delete user'
      color='negative'
      onClick={deleteUser}
    >
      <Menu.Media>
        <Icon glyph={X} />
      </Menu.Media>
      <Menu.Label>Delete user</Menu.Label>
    </Menu.Item>
  </Menu.Popup>
</Menu.Root>;
```

`Menu.Popup` renders the portal and the floating positioner itself — neither is a part you compose
— so items are the only children you write.

### Trigger

With no children, `Menu.Trigger` renders a square ghost `Button` holding an ellipsis glyph. Pass
children for a labelled trigger, or `render` to supply your own element — it receives the computed
props (ARIA attributes, click and keyboard handlers) to spread.

```tsx
<Menu.Trigger>Actions</Menu.Trigger>

<Menu.Trigger render={props => <Avatar {...props} />} />
```

### Items

`label` names the item for typeahead and for assistive technology. Compose the row with
`Menu.Label` and optional `Menu.Media` parts at either end. Text dropped straight into the
item is not a flex child the row can size, so it neither lines up with the other rows nor
truncates. A row with nothing to lead it is `Menu.Label` alone. Use
`color='negative'` for destructive actions; the color is inherited by the children. `disabled` items
are skipped by keyboard navigation and their `onClick` never fires. Activating an item closes the
menu; pass `closeOnClick={false}` to keep it open.

```tsx
<Menu.Item
  label='Revoke'
  color='negative'
>
  <Menu.Label>Revoke</Menu.Label>
</Menu.Item>

<Menu.Item
  label='Delete'
  color='negative'
>
  <Menu.Media>
    <Icon glyph={X} />
  </Menu.Media>
  <Menu.Label>Delete</Menu.Label>
</Menu.Item>
```

### Media

`Menu.Media` is a square column at either end of the row that centers whatever it holds — an icon,
an image, an avatar, a spinner. Items that lead or trail with marks of differing widths need it:
without it each row sets its own text start, and the labels no longer line up. It keeps its width
while empty, so leave it empty on an item that leads with nothing, or render it on any item whose
trailing mark can appear later, and the label does not shift. It renders a `span`, since the item it
sits in is a button.

### Label

`Menu.Label` takes the space between the media and whatever trails it, and truncates its text to one
line. Items whose text is a name — an account, an organization — need it most: a long name would widen
the menu instead of ellipsing. It is also what pushes a trailing mark to the end of the row. Use it
for every composed item, so rows built from parts all read the same.

### Radio items

`Menu.RadioGroup` holds one value, and each `Menu.RadioItem` inside it picks its own `value`. The
checked item carries `aria-checked`, so a screen reader announces which one is current. A
`Menu.RadioItemIndicator` draws a check in the secondary icon color, so use it rather than a check in a
`Menu.Media`. It keeps its column in every row so the labels line up, and shows the check only on the
checked row. Name the group with `aria-label`.

Radio and checkbox items keep the menu open on click, so you can see the change. Pass `closeOnClick`
where picking one is the whole point, as with switching accounts:

```tsx
<Menu.RadioGroup
  aria-label='Accounts'
  value={active}
  onValueChange={setActive}
>
  <Menu.RadioItem
    label='colin@clerk.dev'
    value='colin@clerk.dev'
    closeOnClick
  >
    <Menu.Media>
      <Avatar.Root
        shape='circle'
        size='fit'
      >
        <Avatar.Fallback>C</Avatar.Fallback>
      </Avatar.Root>
    </Menu.Media>
    <Menu.Label>colin@clerk.dev</Menu.Label>
    <Menu.RadioItemIndicator />
  </Menu.RadioItem>
</Menu.RadioGroup>
```

`onValueChange` fires even when the checked item is picked again, so skip work there if you need to.

### Checkbox items

`Menu.CheckboxItem` turns a setting on and off, with `checked` and `onCheckedChange` (or
`defaultChecked`). Its `Menu.CheckboxItemIndicator` works the same way.

```tsx
<Menu.CheckboxItem
  label='Show archived'
  checked={showArchived}
  onCheckedChange={setShowArchived}
>
  <Menu.Label>Show archived</Menu.Label>
  <Menu.CheckboxItemIndicator />
</Menu.CheckboxItem>
```

### Placement

`Menu.Root` takes `placement` and `sideOffset`; the popup flips and shifts automatically to stay in
view, and its `max-height` tracks the available space so long menus scroll rather than overflow.

```tsx
<Menu.Root
  placement='bottom-end'
  sideOffset={8}
>
  …
</Menu.Root>;
```

`sideOffset` also takes `{ x, y }`, one gap per axis, for a menu that can flip between the two: what
it has to clear sideways is not what it has to clear above. `fallbackPlacements` names where it goes
when `placement` does not fit, in the order it tries them, instead of the opposite side. A menu
opened from inside another floating surface wants both — the opposite side is that surface, so it
has to be given somewhere else to land.

```tsx
<Menu.Root
  placement='right-start'
  sideOffset={{ x: 16, y: 8 }}
  fallbackPlacements={['left-start', 'top-start', 'bottom-start']}
>
  …
</Menu.Root>;
```

### Open on hover

`openOnHover` opens the menu when a mouse rests on the trigger, and closes it when the mouse leaves
for anywhere other than the menu. The path from the trigger to the menu is kept open, so the mouse
can cross the gap diagonally. A press still opens it, and keeps a hover-opened menu open until the
next press or an outside click. Touch and keyboard open it as usual.

```tsx
<Menu.Root openOnHover>…</Menu.Root>
```

### Scrolling

A menu with more items than fit gets the shared ScrollArea treatment rather than a bare scrollbar:
the rows fade out at whichever edge still has content past it, and the thumb lifts as the pointer
enters. Nothing to opt into — `Menu.Popup` composes it.

The popup itself only supplies the chrome and the height cap; the rows scroll in a `menu-viewport`
inside it. They cannot be one element, because the fade is a `mask-image` and a mask on the popup
would clip its own background and drop shadow along with the overflowing rows.

### Controlled

```tsx
const [open, setOpen] = useState(false);

<Menu.Root
  open={open}
  onOpenChange={setOpen}
>
  …
</Menu.Root>;
```

## Parts

| Part                         | Slot                             | Description                                                                         |
| ---------------------------- | -------------------------------- | ----------------------------------------------------------------------------------- |
| `Menu.Root`                  | —                                | State provider; owns open/close, placement, and keyboard navigation.                |
| `Menu.Trigger`               | `menu-trigger`                   | Opens the menu. Defaults to a square ghost `Button` with an ellipsis.               |
| `Menu.Popup`                 | `menu-positioner` / `menu-popup` | Portals, positions, and renders the popup surface.                                  |
| ↳ viewport                   | `menu-viewport`                  | The scrolling box inside the popup. Carries the ScrollArea fade and scrollbar.      |
| `Menu.Item`                  | `menu-item`                      | A single action whose content is composed through children.                         |
| `Menu.Media`                 | `menu-item-media`                | Square column at either end of the row. Keeps its width while empty.                |
| `Menu.Label`                 | `menu-item-label`                | The item's text. Fills the row between media and trailing marks, and truncates.     |
| `Menu.CheckboxItem`          | `menu-checkbox-item`             | An item that toggles on and off, announced with `aria-checked`.                     |
| `Menu.RadioGroup`            | `menu-radio-group`               | Holds the value of the radio items inside it.                                       |
| `Menu.RadioItem`             | `menu-radio-item`                | An item that picks its group's value, announced with `aria-checked`.                |
| `Menu.CheckboxItemIndicator` | `menu-checkbox-item-indicator`   | In every row; check shown while its checkbox item is checked. Secondary icon color. |
| `Menu.RadioItemIndicator`    | `menu-radio-item-indicator`      | In every row; check shown while its radio item is checked. Secondary icon color.    |
| `Menu.Separator`             | `menu-separator`                 | Full-bleed divider between groups of items.                                         |

## Styling

The Mosaic menu is themed with **StyleX**. Each styled part
carries a stable `.cl-<slot>` class (the slots above) alongside the StyleX atoms. Consumers never
target the hashed atomic classes — override by targeting the `.cl-*` slot from a CSS layer that wins
over `@clerk/mosaic/styles.css`:

```css
@import '@clerk/mosaic/styles.css' layer(components);

@layer overrides {
  .cl-menu-popup {
    border-radius: 20px;
  }
}
```

The popup's enter/exit transition is driven off its own `data-starting-style` /`data-ending-style`
attributes and is disabled under `prefers-reduced-motion: reduce`. Item hover state is gated behind
`@media (hover: hover)`, and the keyboard-active item is styled off `data-active`, so pointer and
keyboard highlighting stay in sync.
