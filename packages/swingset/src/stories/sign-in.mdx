Enter `locked` as the password to return to the start with the lockout in the banner.

## Usage

The view renders its own `Card.Root` and shows one step at a time inside it. `step` says which step and carries that step's data, such as the code channel or the factors to choose from; every other prop is shared across steps. `form` is one `useForm` holding every step's fields (`SignInValues`), and each step's form submits through `onSubmit`; a completed code goes to `onCodeComplete` with the code. `isPending` describes the current step's attempt, and `isDisabled` locks every control that would start another action, including while a social provider is pending. `errorMessage` is an error about the step's field and shows under it; `globalErrorMessage` is an error about the whole step and shows in the card's banner. The new-password step is the last save, so its errors come from `form` instead. Everything else reports interactions through plain callbacks. One step component can draw several steps: the code step covers the email code, the authenticator app code and email verification, with different copy. `onCancel` is the step's secondary action, "Use another method" or "Back to sign in", and leaving it out hides the button. Leaving out `onResend` hides the resend link, as on the authenticator app step, and `canResend` is false while a resend is waiting or another action runs. `combined` switches the start card to the sign-in-or-up copy; leave out `onSignUp` there to hide the sign-up link. The code, backup code, method picker, and help steps come from the shared verification blocks (`@clerk/mosaic/blocks/verification`), which reverification uses too.

```tsx
import { SignInView } from '@clerk/mosaic/features/sign-in';

<SignInView
  step={{ kind: 'code', purpose: 'second-factor', channel: 'totp' }}
  combined
  applicationName='Acme'
  applicationLogoUrl={logoUrl}
  socialProviders={providers}
  form={form}
  onSubmit={onSubmit}
  onCodeComplete={onCodeComplete}
  isPending={isPending}
  {...callbacks}
/>;
```
