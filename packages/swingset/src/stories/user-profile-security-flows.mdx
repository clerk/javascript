# Security flows

The password, delete-account, and sign-out-all-devices journeys driven by a simulated backend that
takes time, can fail, and can require a stacked reverification challenge.

The failure-point control distinguishes an initial mutation failure from a failed reverification
attempt and a failure when the original mutation is retried. Reverification-only targets appear
only when reverification is required.

The production views render controlled state snapshots and emit events. The state transitions and
simulated backend live only in `user-profile-security-flow.harness.ts`; a Clerk-backed controller
can replace that harness without changing the dialog views.

## Every security-dialog state

Each option sends one controlled snapshot directly to its production view. This makes pending,
failure, set-password, and nested reverification states inspectable without replaying the journey.
