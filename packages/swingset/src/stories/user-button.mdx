# UserButton

The account & organization switcher behind the user avatar. The active organization heads the surface,
badged with the account. The account's organizations sit under it: every one it belongs to, plus
**suggested** and **invited** ones it can Join. **Settings** and **Invite members** follow them, and
**Switch account** at the foot opens the signed-in
accounts as a flyout — the active one checked — so an account never reads as an organization. The
flyout also adds an account and signs out of all of them. With nobody to switch to, that row is
**Add account** instead. The foot signs out of the active account. `mode` narrows all of it;
see [Modes](#modes). For organizations alone, use `OrganizationSwitcher`.

Only the active account's organizations are listed. Not a design choice: org requests are scoped to
the session that makes them, so another account's organizations are unknowable until it _is_ active.
Hence `additionalSessions` carries sessions alone, and `onSelectOrganization` takes no session.

Composed from `Popover`, `Card`, `Item`, `Avatar`, and `Menu`, so behavior, focus, and ARIA come from
them rather than being restyled. `SwitcherView` is presentational; the connected `UserButton` wraps
it with `useSwitcherController()` and needs no props.

## Example

A working prototype over mock accounts — try it. Nothing is instant: the clicked row spins, the rest
stand down, and the surface stays open so you land on the result. Only picking an organization closes it.
`pendingKey` drives that, and the connected `UserButton` sets it from the action in flight. Actions
that would navigate (Settings, Invite members, Add organization, Add account) only close the popover here.

## Usage

`SwitcherView` renders trigger and popup from one prop-driven call:

```tsx
import { SwitcherView } from '@clerk/mosaic/features/switcher/switcher.view';

<SwitcherView
  activeSession={{ sessionId: 'sess_1', userId: 'user_1', name: 'Cameron Walker', identifier: 'cameron@clerk.com' }}
  activeOrganization={{ kind: 'membership', organizationId: 'org_nestlabs', name: 'NestLabs Creative', membersCount: 24, planLabel: 'Pro plan' }}
  hasOrganizations
  memberships={[
    { kind: 'membership', organizationId: 'org_nestlabs', name: 'NestLabs Creative', membersCount: 24, planLabel: 'Pro plan' },
    { kind: 'membership', organizationId: 'org_acme', name: 'Acme' },
  ]}
  suggestions={[{ kind: 'suggestion', id: 'sug_clerk', organizationId: 'org_clerk', name: 'Clerk', status: 'pending' }]}
  invitations={[]}
  additionalSessions={[{ sessionId: 'sess_2', userId: 'user_2', name: 'Cameron Walker', identifier: 'cameron@clerk.com' }]}
  onSelectOrganization={organization => setActive({ organization })}
  onSwitchSession={session => setActive({ session })}
  onSignOutAll={() => signOut()}
/>
```

To drop the popup into your own trigger, compose the parts. Data and callbacks live on
`SwitcherRoot`; the leaves read them from context:

```tsx
import {
  SwitcherRoot,
  SwitcherTrigger,
  SwitcherPopup,
} from '@clerk/mosaic/features/switcher/switcher.view';

<SwitcherRoot {...data} {...callbacks}>
  <SwitcherTrigger />
  <SwitcherPopup />
</SwitcherRoot>
```

Exports are flat (not `UserButton.Trigger`) so each part declares its own `'use client'` boundary.

## Trigger

The avatar and name of whatever leads the popup. With an organization active in `combined`, the
trigger leads with the organization, badged with the account.

`triggerVariant='condensed'` makes the trigger smaller and drops the account's badge. `user` mode is
always condensed.

`renderTriggerBadge` also supports supplying an async function to determine the badge shown alongside the trigger. The function receives an object with `kind` and `id`, and returns an object with `id` and `label`, or `null` to hide the badge. The returned `label` is used as the text content of the label while the returned `id` is embedded into a `data-badge-id` attribute that can then be used to target specific badge types (such as with CSS).

```tsx
<UserButton
  renderTriggerBadge={async ({ kind, id }) => {
    const plan = await (kind === "organization" ? getOrganizationPlan(id) : getUserPlan(id));
    if (plan) {
      return { id: plan.key, label: plan.name };
    }

    return null;
  }}
/>
```

## Header

The header names whatever leads, and carries no actions of its own. An organization is described by
its plan and member count. An account is described by its identifier, and so is an organization the
account badges.

What you can do about the lead sits in its own group, under the organizations: **Settings**, plus
**Invite members** where an organization leads. With an organization active in `combined`,
**Settings** opens a menu of **Manage profile** and **Manage organization**. Where only one of them is
available, **Settings** opens it directly.

## Modes

`mode` picks which switchers the surface carries — the only prop that changes the popup's shape.
Everything else is data.

| Mode                 | Popup                                | Leads with                               |
| -------------------- | ------------------------------------ | ---------------------------------------- |
| `combined` (default) | Organizations and accounts together. | The active org, badged with the account. |
| `user`               | Accounts only; never shows an org.   | The account.                             |

What a mode leads with is named in the trigger and heads the popup — the two always agree.

accounts, with **Add account** and **Sign out of all accounts**, and **Sign out** at the foot signs

## Loading

Memberships, invitations and suggestions are three separate requests, and the popup opens before any
of them land. `organizationsLoading` holds the organization list's place until the last one is in — one
placeholder for all three, so the list does not walk itself in a row at a time. The header is
already known, so it renders throughout.

## Single session

An instance in single-session mode holds one account at a time, so there is nothing to switch to and
no second account to add. It hands the view an empty `additionalSessions` and leaves `onAddAccount`
and `onSignOutAll` off — the surface withholds **Switch account**, **Add account**, and **Sign out of
all accounts**. The foot keeps **Sign out**.

## Profile modal

Mosaic's profile modals are mounted by `MosaicProvider`, so neither the opener nor the app renders a
dialog. The exported UserButton still opens the clerk-js profile. This example backs the modal with
fixture data, so it runs without a Clerk session. The profile is combined: the active organization's
pages follow the account's. **Manage account** calls `open()`, **Manage organization** calls
`open({ page: 'organization/general' })`, and the app's own buttons call `open({ page })` or
`open({ mode: 'user' })` on the same modal. Hovering one preloads the profile, so it opens without a
wait.

## Menu items

`customMenuItems` adds the app's own rows to the group with **Settings** and **Invite members**, after
Clerk's own. A row with `onClick` is an action and closes the popup on the way out; a row with `href`
is a link and navigates on its own, so it stays followable while another action is in flight. The
`icon` is optional — a row without one still holds the column, so labels stay in line. A custom item
whose `id` is `settings` or `inviteMembers` replaces that row, in its place.

`menuItemOrder` names that group's rows by id, and whatever it leaves out follows what it named. The
ids it knows are `settings`, `inviteMembers`, and each custom item's `id`. The organizations above
and the account rows at the foot keep their own order. An id the group has not got is ignored rather
than an error, so one order can cover every mode.

### Avatar

`.cl-user-button-avatar` holds the account's badge on the organization's avatar. The cutout behind
the badge follows its size, so resizing either keeps the gap even. Set `width` and `height` on
`.cl-user-button-avatar` to resize it, and these variables on it to place the badge:

| Variable                   | Default                       | Description                                                     |
| -------------------------- | ----------------------------- | --------------------------------------------------------------- |
| `--cl-avatar-badge-size`   | `14px` trigger, `16px` header | The badge's width and height.                                   |
| `--cl-avatar-badge-gap`    | `1px`                         | The space cut out around the badge.                             |
| `--cl-avatar-badge-offset` | `2px` trigger, `4px` header   | How far the badge sits past the corner of the avatar it badges. |

```css
.cl-user-button-avatar {
  width: 48px;
  height: 48px;
  --cl-avatar-badge-size: 20px;
  --cl-avatar-badge-gap: 2px;
}
```

The trigger's avatar and the header's both read the sliders. A slider left at **default** sets
nothing. Swingset injects its styles at a specificity a plain rule cannot beat, so this example marks
the size `!important`; an app importing the layered stylesheet does not need to. Turn on **RTL** to
see the badge move to the other corner.
