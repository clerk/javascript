# OAuthConsent

Asks the signed-in user whether an OAuth application may access their account. `OAuthConsent` reads the client, scopes and redirect URI from the `client_id`, `scope` and `redirect_uri` URL parameters unless props set them, and posts the answer to Clerk with the other URL parameters forwarded. Every scope starts checked, and the user can clear any of them except `offline_access`; only the checked scopes are posted. When the application asks for `user:org:read` and it stays checked, the user picks which organization to grant. It renders `fallback` until Clerk loads, a skeleton of the consent card until the consent details load, and nothing when nobody is signed in.

## Usage

```tsx
import { OAuthConsent } from '@clerk/mosaic/features/oauth-consent/oauth-consent';

<OAuthConsent />;
```

## Props

| Prop            | Type     | Default                      |
| --------------- | -------- | ---------------------------- |
| `oauthClientId` | `string` | The `client_id` parameter    |
| `scope`         | `string` | The `scope` parameter        |
| `redirectUrl`   | `string` | The `redirect_uri` parameter |

## Examples

### Many scopes

A long scope list scrolls inside its box, with the edges fading while there is more to see.

<Story name='ManyScopes' storyModule={Stories} />

### Single organization

`organizationSelection` with `organizationId` shows a plain select, and the form posts the one picked `organization_id`. `OAuthConsent` uses this when the instance allows one organization for each consent.

<Story name='SingleOrganization' storyModule={Stories} />

### Multiple organizations

The default. `multiple: true` with a `limit` lets the user pick up to that many organizations; `OAuthConsent` uses this when the instance allows more than one organization for each consent, and takes the limit from the consent info. Once the limit is picked, the rest are disabled, and the select reads as a count once more than one is picked. Allow stays disabled while none is picked. The form posts the picked organizations as one space-separated `organization_id`.

<Story name='MultipleOrganizations' storyModule={Stories} />

### Organization access

`multiple: true` with `access` asks whether to grant all organizations or only selected ones. All posts every organization; only selected shows the multi-select, and Allow stays disabled until one is picked.

<Story name='OrganizationAccess' storyModule={Stories} />

### Offline access

Requesting `offline_access` lists that scope as required, so it stays checked, and adds a note that the user stays signed in.
