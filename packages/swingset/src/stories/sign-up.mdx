# SignUp

The standalone sign-up view. It reuses the sign-up screens the sign-in view shows in the combined flow, and adds the screens only a standalone sign-up has.

## Usage

The view renders its own `Card.Root` and mounts one screen at a time inside it. `screen` says which one: a route of the sign-up, or a screen the flow shows on top of a route, such as `restricted` or `startOver`. Each screen takes its own props under its own name, so `start` and `continue` hold the details form and `verifyEmail` and `verifyPhone` hold what a code screen needs. `start` and `continue` share one `useForm`, so what the user typed is still there after a trip to a verify screen. A verify screen sends its code when it mounts with `needsCode`, and `attempt` remounts it for a new sign-up. `taskChooseOrganization` is a slot for the session task shown on its route. Leaving out a callback hides the control it drives: `onSignIn` for the sign-in link, `onCancel` for a screen's secondary action, `onResend` for the resend line, `onEmailSupport` and `onJoinWaitlist` for the restricted screens.

```tsx
import { SignUpView } from '@clerk/mosaic/features/sign-up';

<SignUpView
  screen='start'
  applicationName='Acme'
  start={{ ...details, step: { purpose: 'start', fields: { emailAddress: { required: true } } } }}
  continue={{ ...details, step: { purpose: 'continue', fields: {} } }}
  verifyEmail={{ identifier, needsCode, sendCode, verifyCode, onVerified, onEditIdentifier }}
  verifyPhone={{ identifier: phoneNumber, needsCode: false, sendCode, verifyCode, onVerified, onEditIdentifier }}
  restricted={{ onSignIn }}
  onStartOver={startOver}
/>;
```
